# حالة التنفيذ — وصال (المرحلة 1 / MVP)

> آخر تحديث: 2026‑09‑24

## ✅ مُنجَز ومُتحقَّق منه فعليًا

### قاعدة البيانات (PostgreSQL 17 حقيقي)
- تشغيل PostgreSQL 17.10 محليًا **بدون Docker** عبر `tools/db` (ملفات ثنائية أصلية من npm).
- 24 جدولًا + **285 قيدًا** (PK / FK / NOT NULL / UNIQUE / CHECK) + فهارس جزئية للأداء.
- 7 ملفات هجرة SQL، مطبَّقة بنجاح على الخادم (`npm run migrate`).
- نظام هجرات آمن: معاملة لكل ملف، تتبّع بالبصمة SHA‑256، ورفض تعديل هجرة مطبَّقة.
- لا اعتماد على أي إضافة (extension) — يعمل على أي PostgreSQL 13+.

### العقد المشترك `@wesal/shared` (يُبنى بنجاح)
- أنواع النطاق: الحالات، صلات القرابة (القائمة الجاهزة)، أنواع الجدول، طرق الاطمئنان، مراحل التصعيد.
- نظام التصميم: ألوان الحالة، الثيم الفاتح/الداكن، WESAL RING، الحركة (150–500ms)، أحجام الخط و Senior Mode.
- نصوص `ar` (RTL) و `en` (LTR) **بكامل التطابق** (يضمنه المترجم عبر النوع `WesalMessages`)،
  وتشمل نص تنبيه الجهة الموثوقة المعتمد حرفيًا ونصوص ساعات الهدوء وإرشاد الطوارئ.
- تنسيق الوقت/التاريخ بمنطقة زمنية محددة (أرقام لاتينية للعربية كما في الوثيقة: `8:42 م`).
- عقود الـ API: الطلبات والاستجابات ورموز الأخطاء والمزامنة دون اتصال.

### طبقة النطاق (منطق نقي قابل للاختبار — لا NestJS ولا قاعدة بيانات)
- `WeeklyPattern` — كائن قيمة بقيود صارمة (أيام 1..7، أوقات HH:mm، منطقة زمنية صالحة، حد 4 أوقات/يوم).
- `schedule-engine` — توسيع القاعدة الأسبوعية إلى مواعيد، الاستثناءات (نقل/إلغاء/إضافة)،
  الإيقاف ووضع السفر ✈️، الجدول المؤقت، الموعد التالي، وكله آمن مع التوقيت الصيفي.
- `entry-status` — حساب حالة الموعد (قادم/حان/لم يتم التحقق/مؤجَّل/مُلغى) + مهلة السماح.
- `quiet-hours` — نوافذ عابرة لمنتصف الليل، والتأجيل (لا الإلغاء) احترامًا للراحة.
- `escalation-policy` — أربع مراحل فقط، وبوابة صارمة للطرف الثالث:
  موافقة + جهة **قبلت** الدعوة + تفعيل الميزة + حدود الرسائل + ساعات الهدوء + الإيقاف الفوري.
- `check-in-rules` — مفاتيح عدم التكرار، اختيار الموعد المستهدف، إغلاق المواعيد الأقدم،
  حل تعارضات المزامنة (الأحدث بوقت الجهاز يفوز)، وحد التأجيلات.
- `notification/templates` — كل الرسائل تُبنى من نصوص `shared` فلا تتفرّع الصياغة.

### طبقة التطبيق والبنية التحتية (مكتوبة)
- منافذ (Ports) لكل المستودعات والخدمات + سجلات مسطّحة مستقلة عن TypeORM.
- مستودعات SQL صريحة مُعامَلة (parameterized) لكل الجداول، مع فكّ تشفير الحقول الحساسة داخليًا فقط.
- تشفير AES‑256‑GCM + HMAC بمفتاح مشتق + إخفاء جزئي للعرض (`+20•••••3456`).
- JWT (وصول قصير العمر يحمل `sessionId`) + رمز تحديث عشوائي يُخزَّن كبصمة + تدوير + كشف إعادة الاستخدام.
- OTP: بصمة HMAC، مقارنة آمنة توقيتيًا، حد محاولات، فترة انتظار، حد ساعي، وإبطال الرموز السابقة.
- خدمة الإشعارات: حفظ ثم تسليم (Idempotency)، إعادة محاولة بـ Backoff أُسّي، تتبع حالة التسليم.
- محرّك التصعيد: تقييم المواعيد المفتوحة، معالجة مهام الطابور، الإيقاف الفوري بعد أي تأكيد اطمئنان.
- خدمة الجدولة: توليد أسابيع قادمة (آمن للتكرار)، استثناء يوم واحد، جدول سفر مؤقت، عرض الأسبوع
  حسب منطقة **المستخدم**، وحساب الحالات دفعة واحدة (3 استعلامات لكل الأشخاص).
- حالات الاستخدام: المصادقة/الحساب، الأشخاص (إنشاء/قراءة/تعديل/إيقاف/استئناف/حذف/إبلاغ/من يراني)،
  الاستثناءات، الجهات الموثوقة (دعوة/قبول/رفض/إلغاء/انسحاب + رابط "أنا بخير" بدون تطبيق).

### الأمان
- حواجز إقلاع للإنتاج: رفض `OTP_DEV_MODE=true`، الأسرار الافتراضية، `CORS_ORIGINS=*`، كلمة مرور التطوير.
- `assertProductionSafety` + تحقق كامل من متغيرات البيئة عند الإقلاع (فشل مبكر برسالة واضحة).
- سجل تدقيق يحجب تلقائيًا أي حقل يحوي `phone/code/token/secret/email`.

## 🚧 قيد التنفيذ (الخطوات التالية بالترتيب)

1. **طبقة العرض (presentation)**: Controllers لكل المسارات، DTO validation عبر `class-validator`،
   `JwtAuthGuard` + فحص صلاحية الوصول، فلتر أخطاء موحّد (رمز + رسالة إنسانية بلغة المستخدم)،
   Swagger/OpenAPI، و`helmet` + Rate limiting عبر `@nestjs/throttler`.
2. **العامل (Worker)**: دورة كل `SCHEDULER_TICK_SECONDS` — توليد المواعيد، تقييم الحالات،
   تنفيذ طابور `scheduled_jobs` بـ `FOR UPDATE SKIP LOCKED`، إنهاء الدعوات المنتهية.
3. **الاختبارات**:
   - وحدة: توسيع الجدول (تغيير المنطقة الزمنية، التوقيت الصيفي، الاستثناءات، السفر، الإيقاف)،
     حالات الحدود، ساعات الهدوء، بوابة الموافقة (لا تنبيه لطرف ثالث بدونها)، عدم التكرار.
   - تكامل/e2e ضد `wesal_test`: تسجيل الدخول OTP، إضافة شخص + توليد الأسبوع، تسجيل اطمئنان
     دون اتصال ثم مزامنة، دعوة/قبول جهة موثوقة، الإيقاف الفوري للتنبيهات.
4. **تطبيق الهاتف (Expo / React Native)**: onboarding من 4 خطوات، تسجيل الدخول بالهاتف،
   الرئيسية (تحية + بطاقات + Empty State + FAB)، عائلتي (بحث وفلاتر)، صفحة الشخص،
   WESAL WEEK، سجل الوصال، الإعدادات (فاتح/داكن، تكبير الخط، Reduced Motion، اللغة، من يراني؟)،
   WESAL RING، طابور المزامنة دون اتصال، و RTL كامل.
5. **معاينة حيّة**: بناء نسخة ويب من نفس كود React Native (`expo export --platform web`)
   خلف خادم معاينة يوكّل `/api` إلى الخادم (روابط نسبية فقط).

## معايير القبول (من الوثيقة) وكيف تتحقق

| المعيار | آلية التحقق |
|---|---|
| إضافة أول شخص في أقل من دقيقة | 3 حقول إلزامية فقط + توليد المواعيد والتذكيرات تلقائيًا في نفس الطلب |
| التذكير يصل في وقته والتطبيق مغلق | مؤقتات على **الخادم** (`scheduled_jobs`) + إشعارات محلية مجدولة في التطبيق (لا عملية خلفية دائمة) |
| تسجيل الاطمئنان يعمل بدون إنترنت ويتزامن | `idempotency_key` فريد + `sync_operations` + حل تعارضات بوقت الجهاز + `POST /v1/sync` |
| لا تنبيه لطرف ثالث بدون موافقة | قيد في القاعدة (`rules_auto_requires_consent`) + بوابة في `escalation-policy` + `auto_escalation_enabled=false` افتراضيًا + قبول الدعوة شرط لإنشاء جهة موثوقة |
