# وصال — صلة الرحم 💚 (Wesal – Family Connection)

> **"وصال... لأن من نحب يستحق أن نطمئن عليه."**

تطبيق ويب عربي (RTL) متكامل وقابل للتشغيل فورًا، يجمع بين **صلة الرحم** و**التواصل العائلي**
و**نظام الاطمئنان الدوري** بتصعيد هادئ يحترم الخصوصية.

- واجهة: React + Vite — عربية RTL بالكامل، وضع فاتح/داكن، أيقونات SVG، تصميم زيتوني/ميرمية/كريمي هادئ.
- خادم: Node.js + Express — REST API + JWT + bcrypt.
- قاعدة بيانات: SQLite (better-sqlite3) — 10 جداول بقيود وفهارس، قابلة للاستبدال بـ PostgreSQL.
- جدولة: محرك خلفي يعمل كل 20 ثانية (مواعيد الاطمئنان، التصعيد، التذكيرات، تنبيهات صلة الرحم).
- إشعارات خارجية: نظام معياري (مزوّد `log` للتطوير، `webhook` لأي خدمة SMS/WhatsApp حقيقية).

## 2) خطوات التشغيل

```bash
# الخادم
cd wesal/server
npm install
cp .env.example .env        # اختياري في التطوير
npm run dev                 # http://localhost:4000

# الواجهة (نافذة أخرى)
cd wesal/web
npm install
npm run dev                 # http://localhost:3000
```

حسابات جاهزة (تُنشأ تلقائيًا أول تشغيل):

| الحساب | البريد | كلمة المرور |
|---|---|---|
| تجريبي | `demo@wesal.app` | `Demo@1234` |
| مرتبط عائليًا | `mohamed@wesal.app` | `Demo@1234` |
| إدارة | `admin@wesal.app` | `Admin@Wesal2026` (أو `ADMIN_PASSWORD`) |

## 3) إعداد قاعدة البيانات

لا خطوات يدوية: عند أول تشغيل يُنشأ الملف `server/data/wesal.db` ويُطبق `schema.sql` تلقائيًا
(`CREATE TABLE IF NOT EXISTS` — آمن للتشغيل المتكرر). لحذف كل شيء والبدء من جديد:
`rm -rf server/data`. للانتقال إلى PostgreSQL لاحقًا: المخطط SQL قياسي والاستعلامات
معزولة في `routes/` و`services/` — استبدل طبقة `db/index.js` فقط.

## 4) متغيرات البيئة (server/.env)

| المتغير | إلزامي | الوصف |
|---|---|---|
| `JWT_SECRET` | ✅ في الإنتاج | سر توقيع الرموز — `openssl rand -hex 32` |
| `NODE_ENV` | — | `production` يفعّل حواجز الأمان (يرفض غياب JWT_SECRET) |
| `PORT` / `HOST` | — | افتراضي `4000` / `0.0.0.0` |
| `DB_FILE` | — | مسار ملف قاعدة البيانات |
| `CORS_ORIGINS` | ✅ في الإنتاج | نطاقات مسموحة مفصولة بفواصل (لا تترك `*`) |
| `SMS_PROVIDER` | — | `log` (تطوير) أو `webhook` (إنتاج) |
| `SMS_WEBHOOK_URL` | مع webhook | خدمة تستقبل `{to, channel, message}` |
| `SCHEDULER_INTERVAL_MS` | — | دورة المحرك (افتراضي 20000) |
| `SEED_DEMO` | — | `false` في الإنتاج لتعطيل البيانات التجريبية |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | — | حساب الإدارة الذي يُنشأ أول مرة |
| `SERVE_WEB_DIST` | — | `true` ليخدم الخادم الواجهة المبنية بنفسه |

**لا توجد أي أسرار في الواجهة** — كلها في الخادم عبر البيئة.

## 5) خطوات النشر (Production)

```bash
cd wesal/web && npm ci && npm run build       # ينتج web/dist
cd ../server && npm ci --omit=dev
# .env: NODE_ENV=production, JWT_SECRET=…, CORS_ORIGINS=https://your-domain,
#       SEED_DEMO=false, SERVE_WEB_DIST=true, SMS_PROVIDER=webhook, ADMIN_PASSWORD=…
node src/index.js                             # خدمة واحدة تخدم API + الواجهة
```

- شغّله خلف Nginx/Caddy مع **HTTPS** (إلزامي).
- استخدم `systemd` أو `pm2` لإبقاء العملية حية (المحرك الخلفي يعمل داخل نفس العملية).
- انسخ `server/data/` احتياطيًا دوريًا (ملف واحد).

## 6) شرح وظيفة كل جزء

- **نظام تأكيد الحالة**: `checkin_schedules` لكل مستخدم (يوميًا/يومين/3 أيام/أسبوعيًا/مخصص + ساعة
  بتوقيت المستخدم). المحرك ينشئ موعدًا (`checkins`) عندما يحين الوقت ويرسل «حان وقت الاطمئنان عليك».
- **التصعيد التدريجي** (في `scheduler.js`): 1) تذكير 2) تذكير إضافي 3) الحالة → «بانتظار التأكيد»
  4) إبلاغ الجهة الموثوقة الأولى 5) الجهات التالية بالترتيب. الرسالة ثابتة وهادئة:
  *«مرحبًا، لم يتمكن [الاسم] من تأكيد أنه بخير في الموعد المعتاد. نرجو الاطمئنان عليه.»*
  — لا كلمة «خطر» ولا افتراضات، ويُختبر ذلك آليًا في `core.test.js`. أي ضغطة «أنا بخير» توقف كل شيء فورًا.
- **صلة الرحم**: أقارب بصورة وصلة قرابة وإيقاع تواصل، «تواصل الآن» (tel: / sms: / wa.me) مع تسجيل تلقائي،
  وتنبيه لطيف «لم تتواصل مع والدتك منذ 6 أيام».
- **لوحة العائلة**: ربط حسابات حقيقية برمز مشاركة، وعرض الحالة بألوان هادئة فقط
  (أخضر ميرمية = بخير، كهرماني = بانتظار التأكيد، رمادي = «لم يتم التأكيد» — لا أحمر أبدًا).
- **لوحة الإدارة**: `/admin` — إحصائيات مجمّعة فقط، محمية بدور `admin`، بلا أي محتوى خاص.

## 7) الخدمات الخارجية المطلوبة

لا شيء إلزامي للتشغيل. اختياريًا للإنتاج:
- **بوابة رسائل** لتنبيهات التصعيد (Twilio / Unifonic / Vonage / WhatsApp Business API):
  تُربط عبر `SMS_PROVIDER=webhook` أو بإضافة ملف مزوّد جديد في `services/notify/providers/`.
- **بريد** (اختياري لاستعادة كلمة المرور مستقبلًا). كل شيء آخر ذاتي الاستضافة.

## 8) تعليمات الاختبار

```bash
cd wesal/server && npm test        # 5 اختبارات: أمان كلمات المرور، عزل البيانات،
                                   # CASCADE، رسالة التصعيد، حساب المواعيد
```

اختبار يدوي سريع للتصعيد: فعّل الجدول بوقت قريب، واضبط المهلة والفواصل على 15 دقيقة،
ثم لا تضغط «أنا بخير» — سترى المراحل تتقدم في جرس الإشعارات، وتنبيه الجهة الموثوقة
يظهر في سجل الخادم (مزوّد `log`) وفي `escalation_alerts`.

## 9) الأخطاء المحتملة ومعالجتها

| المشكلة | السبب والحل |
|---|---|
| `JWT_SECRET مطلوب في الإنتاج` | الخادم يرفض الإقلاع عمدًا — اضبط السر في `.env` |
| 401 بعد فترة | انتهاء صلاحية الرمز — الواجهة تعيد توجيهك لتسجيل الدخول تلقائيًا |
| المنفذ مستخدم (`EADDRINUSE`) | غيّر `PORT` أو أوقف العملية القديمة |
| قاعدة البيانات مقفلة | لا تشغّل نسختين من الخادم على نفس الملف (WAL يخفف ذلك) |
| لا تصل إشعارات التصعيد الخارجية | تحقق من `SMS_PROVIDER` و`SMS_WEBHOOK_URL` وسجل الخادم |
| الواجهة لا تصل للـ API | تأكد أن الخادم على 4000 وأن proxy في `vite.config.js` صحيح |
| رمز الربط غير صحيح | الرمز 6 خانات وغير حساس لحالة الأحرف — انسخه من صفحة «العائلة» |

## 10) مبادئ غير قابلة للتفاوض (مطبّقة في الكود)

1. وصال **ليس تطبيق مراقبة**: لا موقع، لا قراءة رسائل، لا تسجيل مكالمات.
2. عدم الرد يعني فقط «لم يتم التأكيد» — لا استنتاج خطر أو مرض أبدًا.
3. لا تنبيه لأي طرف إلا وفق إعدادات وافق عليها المستخدم (ترتيب + سماح لكل جهة).
4. كلمات المرور bcrypt، الجلسات JWT، عزل صارم للبيانات بين المستخدمين، حذف نهائي وتصدير كامل للبيانات.
